# 交付实施助手 使用指南

交付实施助手把一个项目的合同、技术协议、会议纪要、现场日报和问题清单集中到一个工作区，
让你用对话的方式查条款、追进展、判断客户需求是否在合同范围内。
每条回答都附带原文出处，点一下就能看到依据。

---

## 1. 它能帮你做什么

| 你遇到的情况 | 可以这样问 |
|---|---|
| 客户现场提了新要求，拿不准算不算合同内 | “甲方要求在 HMI 上加班次产量报表，在合同范围内吗？” |
| 想不起某个事项的来龙去脉 | “读码追溯这件事现在进展到哪一步了？” |
| 准备验收，要确认标准 | “终验收的标准是什么？SAT 允许遗留哪些问题？” |
| 梳理风险 | “目前还有哪些未关闭的问题？会影响 SAT 吗？” |
| 质保期内客户要求免费更换 | “夹爪指尖磨损了，质保期内要免费换吗？” |
| 新同事接手项目 | “这个项目甲方的对接人分别是谁，负责什么？” |

对“是否在合同范围内”的问题，助手会在回答开头给出明确结论。以“自动化交付”领域为例：

- **范围内**：文档明确包含，或已经书面确认。
- **范围外**：文档明确排除，与约定的规格、数量、品牌或标准冲突，或属于甲方责任。
- **存在歧义**：文档没有约定清楚。会说明歧义点，并建议如何澄清。

> 助手提供依据和建议，不替代商务和合同决策。涉及费用、索赔的结论，请以人工复核为准。

## 2. 安装与启动

### 2.1 环境要求

- Python 3.12 及 [uv](https://docs.astral.sh/uv/)
- Node.js 20+ 及 pnpm（只在需要修改前端时使用）
- 一个 OpenAI 兼容的大模型 API key（DeepSeek 或 OpenAI）

### 2.2 配置

首次运行 `./start.sh` 会自动创建 `backend/.env`（也可以手动 `cp backend/.env.example backend/.env`）。编辑它：

```ini
# 对话模型（必填），以 DeepSeek 为例
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=sk-你的key
LLM_MODEL=deepseek-chat

# 向量检索（可选）。不填则只用关键词检索，项目文档较少时效果差别不大
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_API_KEY=sk-你的key
EMBEDDING_MODEL=text-embedding-3-small
```

改用 OpenAI 时，把 `LLM_BASE_URL` 改为 `https://api.openai.com/v1`，`LLM_MODEL` 改为对应的模型名。

### 2.3 启动

在项目根目录运行：

```bash
./start.sh
```

浏览器打开 <http://localhost:8000>。在终端按 `Ctrl+C` 停止。

- 首次运行会自动安装依赖并构建前端，大约需要一两分钟；之后几秒钟就能启动。
- 还没有 `backend/.env` 时，脚本会先创建它并提示填写 key，填好后再运行一次。
- 提示端口被占用，说明服务可能已经在运行；也可以换个端口：`PORT=9000 ./start.sh`。

## 3. 基本操作

### 3.1 界面

```
┌────────────┬──────────────────────────────┬──────────────┐
│ 项目 [+]    │                              │ 引用原文       │
│ [项目下拉框] │   对话区                      │ （点击引用后    │
│            │                              │   出现）       │
│ 会话 [+]    │                              │              │
│ · 会话 1    │                              │              │
│ · 会话 2    │                              │              │
│            │                              │              │
│ 文档 [上传]  │                              │              │
│ · 合同.docx │ ┌──────────────────────┐ [发送] │              │
│ · ...      │ │ 输入问题              │       │              │
└────────────┴──────────────────────────────┴──────────────┘
```

### 3.2 新建项目

点击左上角“项目”旁的 **＋**，输入项目名称，选择**领域**，点“创建”。每个项目的文档和会话完全独立，不会互相检索。

领域决定助手的身份、给哪几种结论、按什么规则判断，以及空白页上的示例问题。建项目后不能更改，项目下拉框下方会显示当前领域。

| 领域 | 适用项目 | 结论 |
|---|---|---|
| 自动化交付 | 非标设备、自动化产线、系统集成 | 范围内 / 范围外 / 存在歧义 |
| 软件实施 | ERP、MES、CRM 等 ToB 软件实施 | 范围内 / 需求变更 / 待澄清 |

需要其他领域时，可以请开发者在 `backend/domains/` 下加一份配置，见[技术文档](architecture.md#73-系统提示词与领域包-domainspy)。

### 3.3 上传文档

点击“文档”旁的 **上传**，可以一次选择多个文件。

| 格式 | 解析方式 | 引用时显示的位置 |
|---|---|---|
| Word（.docx） | 按标题分节，表格逐行读取 | 章节标题，如“第三章 供货范围” |
| PDF（.pdf） | 按页读取 | 页码，如“第 3 页” |
| Excel（.xlsx） | 每 5 行一组，保留表头 | 工作表和行号，如“工作表「问题清单」第 2-6 行” |
| Markdown / 文本（.md / .txt） | 按标题层级分节 | 标题路径，如“方案评审会纪要 > 新增需求讨论” |

**让回答更准的上传建议：**

- **Word 文档请使用“标题”样式**排章节。这样引用能精确到章节，检索也更准。
- **文件名要能看出内容和版本**，如 `技术协议_V1.2.docx`、`会议纪要_2026-05-09_方案评审会.md`。助手会根据文件名判断文件的新旧和类型。
- **Excel 第一行写表头**。每行都会带上表头字段一起检索，例如“状态：处理中；负责人：孙浩”。
- **扫描版 PDF 暂不支持**：其中没有文字层，上传会提示“没有解析出文本”，需要先做 OCR。
- 旧版本文档如果已经作废，建议删除，避免助手引用过期条款。

鼠标停在文档名上会显示它被切成了几个片段。点击文档名右侧的 **×** 可以删除，删除后立即不再参与检索。

### 3.4 提问

在底部输入框输入问题。**Enter** 发送，**Shift+Enter** 换行。没有会话时，发送第一条消息会自动新建会话，并以这条消息作为会话标题。

同一会话内助手会记住上下文，可以追问，例如先问“HMI 报表在范围内吗”，再问“那读码追溯呢”。
要讨论无关的新话题，点击“会话”旁的 **＋** 开一个新会话。

### 3.5 看懂回答

一条回答由三部分组成：

1. **检索步骤卡片**：比如“✓ 检索文档：HMI 画面 报表 · 6 条结果”。点开可以看到这一步检索到了哪些片段。
   助手通常会换不同的关键词检索两三次。
2. **结论与依据**：先给结论，再分条说明。
3. **引用标记**：正文中蓝色的 `c12` 这类小标签。**点击后右侧会显示该片段的原文**，包括文件名和所在位置。

**如何判断回答是否可靠：**

- 关键结论后面都应该有引用。没有引用的部分，是助手的推理或建议，不是文档原文。
- 点开引用，核对原文是否真的支持该结论。
- 如果回答说“项目文档中未找到”，通常是缺少相应文档，按它的建议补充上传即可。

## 4. 提问技巧

| 建议 | 示例 |
|---|---|
| 说清楚是谁提的、要什么 | ✗ “扫码枪能加吗” → ✓ “甲方质量部要求抓取前读毛坯二维码并上传 MES，算我们的范围吗？” |
| 一次问一件事 | 范围判断和进度追溯分开问，结论更清楚 |
| 用项目里的叫法 | 用文档中的术语（SAT、点表、VMC-03），检索更准 |
| 让它对比 | “合同和技术协议对验收的规定有没有不一致？” |
| 让它给下一步 | “如果判定为范围外，我该怎么回复客户？” |

## 5. 评估（给开发者和负责标注的人）

项目自带一个“变更范围判断”评估集，用来衡量助手判断得准不准，以及对比不同模型和配置。

```bash
cd backend
uv run python -m eval.run --name 我的实验 --repeats 3          # 运行评估
uv run python -m eval.compare                                   # 对比所有实验
uv run python -m eval.review export --results 我的实验         # 导出复核表
uv run python -m eval.review import                             # 导入复核结果
```

以上命令默认评估“自动化交付”领域，其他领域加 `--domain <领域ID>`（需要该领域配置了评估集）。

**复核标签：** 导出的 `backend/eval/review.xlsx` 中，黄色的“复核标签”列可以下拉选择。
“复核依据”列可以写判断理由。保存后运行 `import`，结果写回 `backend/eval/cases.yaml`。
只有填了“复核标签”的行会被修改。

指标说明见 [技术文档](architecture.md#8-评估模块-backendeval)。

## 6. 常见问题

**发送后提示“未配置大模型”**
`backend/.env` 中没有填写 `LLM_API_KEY`。填好后按 `Ctrl+C` 停止，再运行 `./start.sh`。

**上传后提示“不支持的文件类型”**
目前只支持 .pdf、.docx、.xlsx、.md、.txt。旧版 .doc、.xls 请另存为新格式。

**上传 PDF 提示“没有解析出文本”**
这是扫描件或图片 PDF，需要先 OCR 成可选中文字的 PDF。

**回答明显漏了某份文档里的内容**
先确认这份文档已经上传，并且解析出了片段（鼠标悬停看片段数）。再换成文档里的原词提问。
如果文档很长、章节没有使用标题样式，可以把它拆成几份再上传。

**回答引用了已经作废的旧版本条款**
删除旧版本文档；或者在提问时说明以哪个版本为准。

**数据存在哪里？会上传到外部吗？**
项目、文档原件、片段和会话都存储在本机的 `backend/data/` 目录下。
提问时，检索到的文档片段和你的问题会发送给你配置的大模型服务商；
配置了向量检索时，文档片段也会发送给 embedding 服务。
涉密项目请使用有合规保障的模型服务，或私有化部署的模型。

**如何清空所有数据？**
停止服务后，删除 `backend/data/` 目录。

## 7. 当前限制

- 只做问答和判断，还不会直接修改问题清单，也不会生成变更单、周报等文件（已在路线图中）。
- 单用户使用，没有登录和权限管理，不建议直接暴露到公网。
- 不支持扫描版 PDF、图片和 CAD 图纸。
- 评估集基于一个虚构项目，换到真实项目上效果需要重新评估。
